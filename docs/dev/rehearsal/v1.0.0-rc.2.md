### Why `go install` failed

The go command builds a module's zip from the tagged tree, and refuses a
path it does not admit on every platform. The tree at `39184c8e` held two:
`internal/markdown/testdata/fuzz/FuzzOutline/nul`, a name Windows reserves,
and `spec/conformance/vectors/out/path-templates/expected/render-out/Tom &
Jerry's.txt`, whose `'` a module path may not hold. The proxy and the
direct route both failed on them, before any build:

```text
21:24:05Z spec/conformance/vectors/out/path-templates/expected/render-out/Tom & Jerry's.txt: malformed file path "spec/conformance/vectors/out/path-templates/expected/render-out/Tom & Jerry's.txt": invalid char '\''
21:24:05Z go: metais.org/metais/cmd/metais@v1.0.0-rc.2: create zip: internal/markdown/testdata/fuzz/FuzzOutline/nul: malformed file path "internal/markdown/testdata/fuzz/FuzzOutline/nul": "nul" disallowed as path element component on Windows
```

W3-11 (#336, ADR-010 A11) made the conformance vectors a module of their
own, renamed the seed `nul` to `nul-byte`, and added `TestModuleZipPaths`.
`go install …@v1.0.0-rc.2` stays broken, since a published tag is never
moved; the Go proxy keeps the version as it is (ADR-013 D7 item 8).
