```text
11:07:48Z $ curl -fsSL https://metais.org/install.sh | sh

```

**The mechanism.** Once a stable release exists, the step with no
`METAIS_VERSION` already installs `1.0.0`. The pinned install then wrote
the same bytes, and `rehearse.sh install`, which required the file to
change, read that as `install.sh` having left the binary as it was. The
release was right; the harness's check was written for a world with only
prereleases. Its `metais skill` steps were skipped behind the failure, so
the first run did not check `metais skill` after `install.sh`.

**The repair.** #361 (`cab4d4e3`), merged outside the train, made
`rehearse.sh install` remove the binary before the pinned install, so
that install must write it again and report the version. W4-1 (#362,
`93b395d1`) kept that repair and added the released specification's
checks on top of it (`/spec/1.0/`, and `/spec/` leading to it), under
R-W4-1, which #360 records in plan §9
([ADR-013 W4-1's log](../../adr/logs/ADR-013/W4-1.md)). Neither changes a
release or site byte.
