# ADR-007 — W6-4: test compares a container output by its entries

**2026-10-20, PLAN-2026-10-metais-v1 W6-4.** D5 item 3's comparison of a
container by entries landed in `metais test`, with D6 for it: a packed
package's expected containers are read in place. Chapter 13's §13.7 states
it as MTS-AUT-065 to 071; `aut/test-containers` produces every code, and
`aut/test-containers-packed` runs its package packed, with the same
findings. `internal/vectorgen`'s `TestContainerVectors` writes both
vectors' committed zips, and `regenerate.sh` runs it. Readings, where the
text left a choice:

- **The expected container is read by `zipfmt.OpenContainer`:** the
  package reader's profile, steps 1 to 5 and bounds, `--limit` included,
  but for two rules a container breaks by right:
  - ADR-001's sorted-entry rule, which ADR-005 D8 item 8 lifts inside a
    container;
  - step 2's search for a second end-record signature. An entry may be a
    zip itself, stored (ADR-005 D8 items 4 and 7), whose own end record
    then lies in the container's final bytes. Without this, the tool could
    not read the expected container its own `--update` records for a
    stored container entry (`TestTestContainerStoredZipEntry`). The end
    record must still be the file's last 22 bytes, and step 4's walk still
    accounts for every byte.
- **The render's side is compared from the plan, not re-read.** A
  rendered container's entries are its planned entries, and an entry
  whose method is compared is stored by construction. So a render whose
  container exceeds a package bound, such as `entry-ratio`, is still
  compared, while an expected one that does is
  `example.expected_unreadable`.
- **`example.expected_unreadable`'s `reason`** is the code of the
  reader's first finding: `package.container.not_zip`, `limit.package`,
  and the rest.
- **`example.entry_order`** compares the order of the entries both
  containers hold, so it is reported beside `example.entry_missing` and
  `example.entry_unexpected` rather than in their place. Its `index` is
  0-based among those entries, with `expected` and `rendered`.
- **A container entry is compared by its own entries**, its names located
  after its own and a further `!`: `box.zip!inner.zip!c.txt`. Every entry
  finding's `path` is the output's path, and its `entry` is the path
  within the output, without the output.
- **Locations:** at the expected file's path followed by `!` and the
  entry, with the origin `package`; `example.entry_unexpected` with the
  origin `output` at `<output>!<entry>`, as `example.output_unexpected` is
  located.
- **The result keeps ADR-008 D9's three kinds.** A difference inside a
  container is a `missing`, `unexpected` or `differs` at `<output>!<entry>`.
  A container that does not read, and entries in another order, are a
  `differs` of the container's own path.
- **`--update` writes a container whole when any of its entries differs**,
  and not when only its zip's bytes do. A real `--update` drops the new
  codes' findings, as it drops the file comparison's.

**Meeting M3, W6-4 × pack (W6-1).** W6-4 merged second, so it owns the
meeting's vector, `aut/pack-containers`. Its package's one example holds
expected containers that are equal to the render's by entries and not by
bytes. It packs, because pack's test compares containers by entries, and
the packed package tests the same. Its failing source's example holds
entries in another order, and pack refuses it with `example.entry_order`.
Pack's help now lists the new example codes among its refusals, because
pack declares every code test reports.
