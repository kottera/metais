# ADR-007 — W2-3: check's step 5 judges the rules across an array's items (ADR-003 A2)

**2026-10-23, PLAN-2026-10-metais-values-and-rules W2-3.** D2 step 5 gains
the three findings ADR-003 Amendment A2 item 15 adds, MTS-AUT-081 to
MTS-AUT-083, in `internal/author`'s schema statics.

- **D3, what "declared" means.** A key pointer's tokens are resolved by D3
  item 4's applicable set, the one `schema.required_not_declared` uses:
  the statics' `declared` and the new key resolution share one walk of the
  applicable set and one resolution of a property segment, which returns
  the subschemas the segment reaches. The array's item schema is the
  `items` and `prefixItems` of every node of the array schema's applicable
  set; an array with none, or an open set anywhere along the key, declares
  every token and refuses no value.
- **D2 step 5.** A `coverage` value is unsatisfiable when every schema its
  key reaches refuses it, so a value one alternative accepts is not
  reported; `values` beyond the holding object's `maxItems` is
  unsatisfiable at `values`; a pointer with an undeclared token is
  `schema.key_not_declared`, a warning, once per pointer. ADR-003's log
  records the registry and the vectors.
