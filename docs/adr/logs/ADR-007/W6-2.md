# ADR-007 — W6-2: the scaffold pinned through pack, and the example-package harness

**2026-10-20, PLAN-2026-10-metais-v1 W6-2.** D1 item 7's pin is
`TestInitScaffoldPinned` in `internal/cli`. It runs `init`, then `check`,
`test` and `pack` on the scaffold exactly as `init` writes it, and `check`
of the package `pack` wrote. Each step must succeed with no finding at all,
`test` must pass the scaffold's one example, and none of them may write into
the scaffold. It runs in every `go test`. Its run on every supported
platform is plan §6's matrix act.

The example-package harness of plan §12 (SC4's) is `TestExamplePackages`,
in `internal/cli`. Over every directory directly under `examples/`, it
requires each of these to succeed with no error and no warning:

- `check`;
- `test`, which must pass every example, with at least one example;
- `pack`, whose package must be the size it reports and must check and
  test green again;
- for `--optional all` and `--optional none`, `render --sample`, whose
  written tree must be exactly the files its result lists, with their
  sizes, digests and modes;
- `sample` in the same mode, then `validate` of that data, then `render`
  of it, whose output must equal the preview byte for byte.

Nothing may be written into the example. With no package under
`examples/`, which is so until Wave 7, the test skips and says it ran over
none. `TestExampleHarness` proves the harness on the scaffold, which it
passes, and on packages with a check warning, a failing example, no
example, and an input the generator cannot make. Each of those fails on
the step that shows it.
