# ADR-004 — W2-7: a template-path guard against an `alternative` for a near-name

**2026-10-23, PLAN-2026-10-metais-values-and-rules W2-7.** A correction
from Wave 2's verification, of W2-1 (PR #294, merge `bd2ad7ef`, its log
entry [W2-1.md](W2-1.md)). W2-1.2 asks that a filter name outside the
three money names, one a single edit away from `money` or `amount`
included, be refused with no `alternative`, proved by a vector.
`flt/money-near-names` refuses those names, but ADR-011 D10 item 2 matches
a vector's expected params as a subset of the actual finding's, so no
vector can see a parameter that ought to be absent. The verifier added a
near-name row to the alternatives table, then gave every template
`unknown_filter` an `alternative`; the vectors and `internal/template`'s
tests stayed green under both.

- **The guard.** `internal/template`'s `TestUnknownFilterAlternative`
  parses a template applying each name and asserts that the one
  `template.unknown_filter` finding names it, that `money`,
  `money_with_currency` and `money_without_currency` carry the
  `alternative` `amount`, and that `moneys`, `mony`, `Money`, `amout`,
  `amounts`, `money_with_currencies` and `frobnicate` carry none. It goes
  red under each of the verifier's mutations applied alone. W2-1.2 is met
  by the vector and this test together; `internal/loader`'s test of the
  same name guards the manifest-expression path.
- **No defect.** Every near-name is refused without an `alternative` on
  `main`. No line under `spec/` and no harness code changes.
