# ADR-004 — W2-2: the examples write their values through Amendment A2's filters

**2026-10-23, PLAN-2026-10-metais-values-and-rules W2-2.** Candidate V4 of
plan §7. The three examples that write dates, amounts, counts, percentages
or durations for a person now write them through `date`, `number`,
`amount` and `duration`, as chapter 13 §13.9 teaches. No line under
`spec/` changed, and no schema rule changed.

- **`examples/dora-incident-report`.** Its seven date-time fields are
  written `%-d %B %Y, %H:%M:%S %Z` (`2 March 2026, 06:40:00 UTC`), which
  names the month and the offset and keeps the seconds the glossary's type
  holds. Its counts are written with `group: ","`, and its percentages with
  `decimals: 1` and ` %`, the one decimal the glossary allows. Its three
  monetary fields are written by `amount` with the code taken from
  `entity.reporting_currency` (1.15), which the entity schema requires, and
  `group: ","`: `EUR 48,920,000.00`. Its duration and service downtime,
  held as `DD:HH:MM`, are read with `fields: "d:h:m"` and written
  `%d d %-H h %-M min`, so `00:07:25` is `0 d 7 h 25 min`. The report's
  labels are the glossary's English, so its separators are English ones.
- **`examples/status-widget`.** The text inside `<time>` is written
  `%-d %B %Y, %H:%M %Z`; the `datetime` attribute keeps the RFC 3339 value
  HTML requires.
- **`examples/accessibility-conformance-report`.** The report date in
  `acr.docx`'s body is written `%-d %B %Y`. `acr.json`'s `date` member and
  the Office core properties' `dcterms:created` keep their machine form.
  W1-3's Level A and AA rule and R-W1-c's remarks rule are untouched.
- Every example's expected trees were regenerated by `metais test --update`,
  and the tests that pinned the old text, `TestSC3StatusWidget`'s fragment
  and the ACR's report-date paragraph, were updated to the new one.
