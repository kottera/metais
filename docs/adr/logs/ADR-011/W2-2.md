# ADR-011 — W2-2: the specification at `/spec/draft/`, and each released revision at `/spec/<M>.<m>/` (Amendment A8 items 1 and 2)

**2026-10-23, PLAN-2026-10-metais-public W2-2.** A8 items 1 and 2 are
implemented on the site.

- **The draft (item 2).** Every Markdown file of the checkout's `spec/` is
  a page under `/spec/draft/`, `README.md` at `/spec/draft/` itself. Every
  page there begins by saying it is a draft, names the commit, and carries
  `<meta name="robots" content="noindex">`. `TestSpecPages` holds both.
- **The releases (item 1).** Each `spec-<M>.<m>` tag's files are a page
  each under `/spec/<M>.<m>/`, from the tag's own text, neither called a
  draft nor kept from search engines. The build step exports every
  released page in one list, `release_pages`, since an output's
  `for_each` iterates one array. `/spec/` leads to the latest released
  revision, by a meta refresh and a canonical link to it. No `spec-*` tag
  exists, so `TestSpecReleases` renders the package with two releases,
  1.2 and 1.10, in its specification input, and requires each page, the
  lead to 1.10, and every link to resolve. `TestSpecInput` holds the
  export of tags to the list.
- **`/spec/` while no revision is released.** There is no released
  revision to lead to, so `/spec/` says that none is released yet and
  links `/spec/draft/`. It does not redirect to the draft, which is not
  the specification's canonical home, and it asks search engines not to
  index it, as the draft does.
