# ADR-011 — W6-14: the measuring stub is a small program of its own

**2026-10-20, PLAN-2026-10-metais-v1 W6-14.** On linux, D13 item 2's
`ru_maxrss` is read through a stub that starts each process, so that the
peak is the process's own. The stub was the test binary executed afresh.
Under `-race` that made every process the runner started pay for a
race-built program's start, about 42 ms of CPU. When the tool was not
race-built, as the release build that `TestHostIsolation` runs is not, it
also paid the race runtime's one-second sleep at exit (`atexit_sleep_ms`),
because only a race-built tool's environment carries `GORACE`. With a
runner slot held through that second, `TestHostIsolation`'s 10,992
processes took 23 minutes on a 12-core linux host at `-parallel 4`, and
`internal/conformance` passed `go test`'s ten-minute timeout in the scoped
gate. darwin starts each process directly and never paid either cost.

The stub is now `internal/conformance/testdata/procstub`, a program of its
own that `TestMain` builds without the race detector. The reference driver
finds it beside itself. Every process gets exactly the environment its step
gives it, as before. `TestStubIsItsOwnProgram` pins that the stub is
not the test binary, is not race-built, and passes the environment
through exactly. No check, vector, path mode, environment or channel
changed, and no timeout or share. On the same host at `-race -parallel 4`,
`TestHostIsolation` alone went from 1,406 s wall and 835 s CPU to 53 s
and 395 s. The whole package at `-p 4 -parallel 4` takes 272 s and
2,105 s of CPU.
