# ADR-011 — W2-4: the specification's tag pushed by release.yml (D5 item 2), and the site redeployed for an erratum (A8 item 1)

**2026-10-23, PLAN-2026-10-metais-public W2-4.** `release.yml` pushes
`spec-<M>.<m>` when the draft names the specification's release commit,
in a `Specification release: spec-<M>.<m> <commit>` line of its body.
First it checks that the commit is an ancestor of the release's target and
holds `spec/conformance/released/<M>.<m>.sha256`, and that the release's
tool implements the revision. A prerelease never names one (A8 item 5). A
release that is not a prerelease is refused unless every revision its
tool implements is tagged on GitHub or named by the draft (D5 item 6).
`pages.yml`, dispatched with a published release's tag, rebuilds and
redeploys that release's site, which is how an erratum is published (A8
item 1). `docs/dev/release.md` has both.
