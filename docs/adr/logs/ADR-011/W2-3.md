# ADR-011 — W2-3: a prerelease may implement a draft revision (A8 item 5)

**2026-10-23, PLAN-2026-10-metais-public W2-3.** A8 item 5 takes effect.
The release builder's `checkImplements` refuses a tool whose `implements`
names an unreleased revision only when the version has no prerelease
suffix, as D5 item 6 requires of a release. A version with one, such as
`1.0.0-rc.1`, builds, and the builder names each unreleased revision it
implements in its report. Both kinds of version still refuse a tool that
implements nothing, or names something that is not a revision `M.m`, and
every other refusal is unchanged, the twin-build comparison among them.

- **Tests.** `TestReleaseRefusesAnUnreleasedRevision` pins both sides over
  each way a revision can be unreleased: no tag, a lightweight tag, a tag
  off `HEAD`'s history, no released list. `1.0.0` is refused in each, and
  `1.0.0-rc.1` of the same tree reaches the build. The prerelease side was
  red with the rule removed. Nothing after the implements check depends on
  whether the version is a prerelease, so reaching the build is the whole
  property, and `TestReleaseBuildsTwiceAndWritesDist` proves the rest.
- `docs/dev/release.md`'s "What it checks" states the rule.
