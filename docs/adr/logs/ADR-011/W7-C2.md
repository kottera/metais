# ADR-011 — W7-C2: the runner starts its processes from a spawner, and runs the suite once

**2026-10-20, PLAN-2026-10-metais-v1 W7-C2.** On darwin, Go starts a
process by fork(2), and the runner started every process from the
race-built test binary. A fork marks every page of the forking process
copy-on-write, and the forking process then takes a fault on the next
write to each one. The race detector writes its shadow memory on every
access, so after each fork the test binary re-faulted its whole working
set. `TestHostIsolation` alone at `-race -parallel 5` started 11,429
processes. Its test binary took 11.0 million minor faults and 401 s of
system time, against 39 s of user time. Its children used 214 s in all.
A toy race-built program that writes 200 MiB while forking showed the
same: its writes slowed a hundredfold. Linux starts a process by
clone(2) with `CLONE_VFORK` and `CLONE_VM`, which shares the address
space, and never paid it.

The runner now starts every process, on a unix that forks, through
`internal/conformance/testdata/spawner`. This is a small program that is
never race-built. `TestMain` builds it, and the runner starts it once.
It serves a gob-encoded request for each process: program, arguments,
working directory, exact environment, standard input, wall clock and
stream cap. It answers with the streams, the exit, the CPU time, the
`ru_maxrss` and whether the wall clock killed the process. A fork from
the spawner is cheap. The slots, the counters and every check stay in the
runner. `TestProcessesStartFromTheSpawner` pins three things, and was
seen red with the spawner bypassed:

- the process's parent is the spawner, not the test binary;
- the spawner is not race-built;
- the process gets exactly its environment, working directory and input.

With the spawner, the same `TestHostIsolation` run took 95,000 faults and
44 s of system time.

`TestRealToolInRecord` ran `TestConformance` again in a child test binary,
over every vector, at the child's default `-test.parallel` rather than the
gate's share: 624 s of CPU. `TestConformance`'s default run now records
itself, and `checkRealToolRecord` checks that record. It is valid under
the record schema, and it names the identity `version --json` reports.
Every vector is still recorded against the real tool, and the suite runs
once. `TestRecordAndCompare`'s child runs now get the parent's
`-test.parallel`.

The stream cap is now enforced. `capped` embedded `bytes.Buffer`, so the
copy os/exec makes of a process's stream reached the buffer's `ReadFrom`
and kept everything past `maxInflate`. `TestCappedHoldsThroughCopy` pins
it, and was seen red first.

No vector, case, environment, check, crash check or reach changed, and no
timeout or share. On the dispatch host, darwin/arm64 with 16 cores, the
package at `-race -count=1 -p 5 -parallel 5` went from 336 s wall and
2,288 s of CPU to 163 s and 957 s. `TestConformance`'s default run takes
26 s. Under `-race` it takes 63 s, as before. Its race-built tool
processes (D11 item 2) account for most of that time.
