# ADR-011 — W7-1: A4's absent and unreadable setups, A6's run-time names and file-size limit, and no unwired list

**2026-10-20, PLAN-2026-10-metais-v1 W7-1.** A4 items 1 to 3 landed as Ed
ruled them, and A6, proposed here, gives the two codes A4 could not reach
their vectors. `TestFindingCodesCovered` now ends with no exemption list:
`internal/finding/testdata/unwired.txt` is removed, because it is empty.

- **A4.** The vector schema's setup gains `absent` and `unreadable`, and
  its requirements `unreadable-files`; `spec/conformance/README.md` says
  what each does. The vector schema has no copy embedded in the tool: the
  runner reads the suite's own, so the one file is the schema. In the
  runner:
  - an `absent` path is copied from nothing, and a step may name it;
  - `referenceProblems` does not require it in the vector's directory;
  - `setupProblems` makes a listed path that the vector's directory holds,
    or that no step names, a harness error;
  - `checkAbsent` makes one that exists in the work directory before the
    first step a harness error;
  - `sealUnreadable` gives each `unreadable` path mode 0000, last of all,
    and `unlock` gives it its mode back. The snapshot records a sealed
    path by its type and mode alone, since nothing can read it;
  - `probeUnreadable` probes `unreadable-files` as `probeUnwritable`
    probes `unwritable-dirs`.

  `setupmembers_test.go` proves each harness error with a test that
  fails without its check, each seen red with the check removed.
- **The codes A4 wires.**
  - `package.not_found` names MTS-PKG-001. `pkg/operand-not-found` runs
    its `open` steps, a missing path and a path beneath a missing
    directory, through every opening command, as a security vector's are.
  - `package.not_readable` names a new statement, MTS-PKG-046.
    `pkg/operand-not-readable` does the same for a source directory and a
    file of mode 0000.

  Both stay class `refused`. `input.not_readable` names MTS-SUP-030
  (ADR-003's log, W7-1).
- **A6, under the plan orchestrator's ruling of 2026-10-20** (plan §13,
  "Rulings made during the wave": a code whose input name cannot live in
  the committed suite tree gets a run-time setup). It is proposed for
  Ed's ratification at the train's close.
  - `renames` and `nonportable-names` give `collection.item_name` its
    vector, `sup/collection-item-name`, with D9 item 8's portable-name
    rule for the committed tree untouched.
  - The ruling covers `output.destination.write_failed` too, because no
    existing setup reaches it (A6 item 5). `file_size_limit` and
    `file-size-limit` give it `aut/unpack-write-stopped`. The limit is
    set by a stub, `testdata/fsizestub`, which sets `RLIMIT_FSIZE`,
    ignores `SIGXFSZ` and executes the step's process in its place. It
    is built, like the measuring stub, without the race detector, the
    first time a case or the probe needs it.
  - Each probe skips only where the host cannot make the name or the
    limit. On this item's darwin host every one of the new requirements
    was met, and every new vector ran.
- **The unwired list is gone.** `TestFindingCodesCovered` and its control
  no longer read a list, and fail on any registered, unretired code of
  class `refused`, `content` or `destination` that no vector produces.
  The control was seen red for each class, and the real test was seen
  red with `sup/collection-item-name` taken away. `internal/cli`'s
  refusal tests no longer read the list either: inspect's makes a missing
  path and an unreadable directory itself, as the suite's setups do.
