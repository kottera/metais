# ADR-011 — W7-2: chapter 15, Appendix A, the front page, and a sweep of the 1.0 text

**2026-10-20, PLAN-2026-10-metais-v1 W7-2.** The specification's 1.0 text
is complete. The front page still reads `Status: Draft`, `Latest release:
none`, and `CHANGELOG.md`'s 1.0 section still says "First revision." and
`unreleased`: nothing of the release act is done.

- **Chapter 15 (D1 item 2, D8 to D16).** It states what a conformance
  claim names (MTS-CNF-001, D8 item 4) and when a program meets its claim
  (MTS-CNF-002); the operations of D8 item 2's table, each with its
  arguments and results as the owning chapter defines it now, `fail_on`
  among render's and `optional`, `seed` and `items` among sample's; what
  `ok` means (MTS-CNF-003); that a program performs each operation with
  those arguments and gives those results (MTS-CNF-004); the suite's
  layout, as `spec/conformance/README.md` describes it after W7-1's A4 and
  A6 members; how a step is judged (MTS-CNF-005, D10 and D13); that only an
  unmet `requires` skips a case (MTS-CNF-006, D9 item 6); and, informatively,
  the two environments, the driver protocol and the cross-platform record
  (D11, D12, D15). As this ADR's *Conformance* section says, the statements
  about claims are `not observable`. MTS-CNF-003 is observable and
  `cnf/ok-error-severity` proves it; every other CNF statement is `not
  observable`, with a note naming how `metais` is proved to meet it.
- **A vector's class, and a new check in `TestVectorsWellFormed`.** D8
  item 4 satisfies a claim with every vector of the claimed classes, so a
  processor vector that runs `check` cannot be passed by a program that
  claims the processor class alone. `aut/check-container-profiles`, which
  only runs `check`, is now class `authoring`, and the `check` case of each
  of the seven `man/hostile-*` YAML vectors moved to a vector of its own,
  `man/hostile-<name>-check`, class `authoring`, with the same package,
  findings and bounds. `TestVectorsWellFormed` now fails a processor vector
  with an authoring tool's operation, a render with `sample` included; it
  was seen red on exactly those eight vectors, and its control breaks the
  fixture's vector the same way.
- **Appendix A.** It lists every document a chapter relies on, each with
  its anchor, and each first reliance links it: RFC 3629, RFC 5321, FIPS
  180-4, IEEE 754, ISO 8601 and POSIX's pax format, normatively; ECMA-376,
  ODF 1.3, EPUB 3.3, liquid-spec at the pinned commit, Git's CVE-2014-9390
  release notes and Microsoft's naming rules, informatively. A new
  tripwire, `TestLinksResolve` in `internal/guarantees`, holds every link of
  the specification's documents outside code to a file that exists and to
  an anchor or heading of the document it names; its control turns it red
  on a missing document, a missing anchor and a link resolved from the
  wrong directory.
- **The front page** links every chapter and appendix, and now the suite's
  description, the published schemas and the finding-code registry too.
- **The sweep.** These gaps in the text were in this item's scope, and are
  fixed without a new statement:
  - chapter 14's summary promised a threat model it did not hold. It is now
    §14.1 (informative), from ADR-009 D1, and the later sections are
    renumbered;
  - chapter 5's summary promised the `inputs` section and the meaning
    documents, and no chapter stated an input declaration's members. They
    are now §5.1, from the manifest schema, and the later sections are
    renumbered;
  - chapters 2 and 11 refused "a `.git` segment in any spelling Git treats
    as `.git`" without saying which those are. Chapter 2 now defines them as
    the reference tool implements them (ADR-009 D8 item 6);
  - MTS-SMP-009's "the same options" named options chapter 13 never named,
    and §13.6 now names them;
  - `container-depth`, which MTS-TRN-003 bounds, had no row in chapter 14's
    tables, and has one now;
  - §12.2 said only five members of a finding are compared, while §12.3
    defines four more and the suite compares `related` too. It now names
    every member the suite compares, and defines a code's class, which
    MTS-AUT-003 and the catalog use;
  - MTS-AUT-046 spoke of "a note", which is no severity, and now says info;
  - two references pointed at chapters that do not define the term: the
    declared type set is chapter 6's (§6.7), and an input's name rule is
    now chapter 5's §5.1;
  - MTS-SEC-042 relies on Go's `regexp/syntax`, now in Appendix A at the
    module's toolchain;
  - `spec/conformance/README.md` said a driver's listing holds `path`,
    `size` and `digest`, while the suite compares every member of
    MTS-RND-009's records. It now says so, as chapter 15 does.

  One gap is outside this item's statement blocks and is left for the
  closeout: the tool enforces a `regex-work` limit (default 2³³) on schema
  pattern matching, which no chapter names. Stating it takes a SEC
  statement, its table row and a vector.
