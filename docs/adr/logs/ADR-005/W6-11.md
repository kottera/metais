# ADR-005 — W6-11: every path case of the Conformance section is a vector

**2026-10-20, PLAN-2026-10-metais-v1 W6-11.** The *Paths* cases of the
Conformance section are vectors. `pth/output-paths` holds the forms, the
characters, the reserved names and the 255- and 256-byte segments of a path
the manifest writes. `pth/output-path-collisions` and
`pth/data-path-case-collision` hold the collisions by case, by full folding
and between directory prefixes. `pth/output-path-limits` and
`pth/data-path-limits` hold the length boundaries at lowered limits. The new
`pth/data-path-predicate` adds what none of them held, rendered from data,
both sides of each boundary in one data file:

- a code point of every general category D12 item 2 refuses, among them
  U+FFFD, a zero-width joiner, an unassigned code point and the separators
  other than U+0020, beside one of each it accepts;
- every reserved name bare, with one and two extensions, with spaces before
  its extension and with `¹`, `²` and `³`, every `.git` spelling, and near
  misses of both;
- 512 and 513 bytes and 32 and 33 segments at the default limits;
- NFC beside NFD, and a file beside a directory of its name.

D12 item 4's superscript digits and its trim of the spaces before a name's
`.` were in the tool but not in chapter 11's text. MTS-PTH-010 states them,
which is the stricter rule. Chapter 2's statement of the same rule for entry
names still lists only `com0` to `com9` and `lpt0` to `lpt9`.
