# ADR-013 — W2-10: the install scenarios of D9

**2026-10-23, PLAN-2026-10-metais-public W2-10.** D9's two scenarios are
in the UX harness, with their outcome checks in the scorer, and they run
in Wave 3 as an out-of-band act on Ed's host.

- **The scenarios.** `I1-install-and-render` is C1 with metais to install
  first: the DORA report package and the prompt "install metais from
  metais.org and render this file: report.metais". Under R-UX-5 a real
  document is asked for, not invented, so I1's outcome check is C1's
  `asks-not-invents`, with a recorded verdict before its scorecard
  counts. `I2-discover` is A1's prompt as it stands. A scenario's
  declaration gains `install`, which exactly the `I<n>` scenarios set,
  and an I scenario may be of either kind (I1 consuming, I2 authoring).
- **The runner.** An install scenario's session gets the runner's
  `PATH` alone, with no metais under test before it, and its isolation
  check is `metais-not-on-path` in place of `metais-first-on-path`, which
  every other scenario keeps unchanged. Its session also gets
  `GOFLAGS=-modcacherw`, so the runner can remove a module cache a
  `go install` made when it runs the run again. An I scenario runs only
  when `-scenarios` names it, and `-with-skill` refuses one.
- **The scorer.** `golden-install` is a pass rule of the consuming I
  scenarios: the last install before the first metais that ran is a
  golden path of D6 item 1. `finds-and-installs` is I2's check: a metais
  it installed ran, by any route, which the detail names, with A1's
  `new-package` recorded as a note. The scorecard shows the I scenarios
  in their own section, counts I1 towards D9's gate apart from R-UX-5's
  thresholds, and marks I2 recorded on every model.
- **The fixtures.** Two runs recorded in a dispatch before metais.org had
  an address (I1 and I2 on Haiku) each fail where they should; three
  `edited-*` fixtures from recorded C1 and A1 runs pass `golden-install`
  and `finds-and-installs`, and fail `golden-install` by `go install`.
- **Where they run.** A nested session in a dispatch reaches GitHub,
  Homebrew's API and the Go module proxy directly, but metais.org had no
  address, and `brew` cannot run under the dispatch's sandbox. So the I1
  and I2 runs are an out-of-band act on Ed's host in Wave 3;
  `docs/dev/ux-testing.md` says what the act must provide, a credential
  route for the nested sessions among it.
- **No ADR-009 amendment.** The runner uses no symbol beyond ADR-009 A8's
  allowance, and hands a session no more of its own environment, so A13,
  allotted to this item, stays unused.
