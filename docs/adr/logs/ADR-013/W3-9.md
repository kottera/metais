# ADR-013 — W3-9: release.yml parses on GitHub, and the tripwire refuses a context GitHub does not admit (D5 item 1, D7 item 3.2)

**2026-10-24, PLAN-2026-10-metais-public W3-9.** Written at the train's
close, 2026-10-26, by W4-3: the change wrote no entry, and this one is
drawn from its merged pull request, #333 (merged as `39184c8e`), and the
Wave 3 closeout. W3-9 was filed as Work Order `01a16f18-3349` and
cancelled, and the change was made in Ed's release act W3-OOB4, under the
item's address.

D7 item 3.2's `release.yml` was refused by GitHub before any run existed:
its job-level `env` named `runner.temp`, a context GitHub admits only in a
step. Wave 2 had proved the workflow by running its steps by hand, so
GitHub had never parsed it. Each step now names `"$RUNNER_TEMP/release"`,
and nothing else in the workflow changed. D5 item 1's tripwire,
`TestWorkflows`, now refuses a context GitHub does not admit in a
workflow's `env`, a job's `env` or a job's `if`, with seven rows in
`TestWorkflowsControl`, so such a workflow fails in CI rather than at its
first dispatch. actionlint 1.7.12 found no other defect. rc.1's draft
stood, since `release.yml` runs from `main`.
