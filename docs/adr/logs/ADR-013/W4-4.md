# ADR-013 — W4-4: go install @latest checked against v1.0.0, and by the rehearsal

**2026-10-26, PLAN-2026-10-metais-public W4-4.** A corrective filed by
the wave's verification (Work Order `01a17a14-4f6a`). The brief's launch
checks list `go install metais.org/metais/cmd/metais@latest` (D6 item
1), and the launch checks' run, 40396621692, installed `@v1.0.0` only:
`rehearse.yml` (D7 item 8) had no `@latest` step. It changes no release
or site bytes.

- **The check against `v1.0.0`, by hand.** Run with the default
  `GOPROXY` and an empty module cache, `GOPATH` and `GOBIN` under a
  temporary directory, outside any module. `@latest` installed
  `metais.org/metais v1.0.0`, whose proxy record names `f7f57020` at
  `refs/tags/v1.0.0`, and the binary reports `metais 1.0.0`. The
  commands, their output and the time are in the
  [launch record](../../../dev/rehearsal/v1.0.0.md). It is one install
  on one machine, not a GitHub-hosted runner, so `docs/INDEX.md`'s row
  stands and is now true of every check of the brief's list.
- **The rehearsal's step.** `rehearse.yml`'s go-install job classifies
  the version: one whose version, before any `+` build metadata, has a
  `-` suffix is a prerelease, and `@latest` never resolves to it while a
  release exists. For a release, `go install ...@latest` runs through the
  Go proxy into a `GOBIN` and a module cache of its own, and `rehearse.sh
  version` requires `metais <version>`. For a prerelease the step says so
  and neither runs. Both run whether or not a step before them refused.
  `TestRehearseWorkflow` requires the steps, their condition, their
  `GOBIN` and module cache, and runs the classifying step's script for a
  release, a prerelease and versions with build metadata.
  `docs/dev/release.md`'s table says what the step does. The next
  dispatch of `rehearse.yml` against `1.0.0` checks it on a runner.
- **Two cases of `TestRehearseScript` the verification found blind.**
  `released, its chapters read from its tag` now commits a chapter after
  the `spec-1.0` tag, so a check reading `HEAD` instead of the tag, as
  well as one reading the working tree, is refused. `latest, a release
  installing another version` gives `latest 1.0.0` an `install.sh` whose
  binary reports `0.9.0`, and requires the refusal, so the stable
  branch's `--version` comparison is pinned. Each new assertion was made
  red by mutating the line it guards.
