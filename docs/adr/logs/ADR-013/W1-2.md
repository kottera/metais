# ADR-013 — W1-2: the history scan, the tree's internal details and a self-contained AGENTS.md (D3 item 4, D4 items 2 and 3)

**2026-10-22, PLAN-2026-10-metais-public W1-2.** The whole history was
scanned for secrets and none was found, so nothing was rotated; the
current tree names no internal host and no person's machine; and
AGENTS.md states the naming rules it used to point at.

- **The scan (D4 item 2).** gitleaks 8.30.1 scanned a mirror clone of
  `kottera/metais`: every commit reachable from every branch and pull
  request ref on the remote, which holds no tag. trufflehog 3.99.3
  scanned the same mirror, without verification. Neither reported a
  finding. Both scanners were installed outside the checkout. The report,
  with the commands, is an artifact of the item's Work Order and is not
  committed. History is not rewritten (R-PUB-7).
- **The tree (D4 item 3).** Every baseline under `testdata/bench/` labels
  its host by platform, and the ADR-010 log entries T-A2 and W6-A2 do the
  same for their measurement hosts. The plans, briefs,
  `docs/dev/ux-testing.md` and this ADR describe a run outside a dispatch
  by its procedure, a run by hand outside the dispatch sandbox, instead
  of by whose machine it ran on. `docs/dev/benchmarks.md` asks for the
  platform and never the host's name, so a new baseline does not bring a
  name back. The scrub and host-fact tests use synthetic user names. No
  tailnet URL was in the tree. Work Order IDs stay, and so does the module
  path in records (W1-1).
- **AGENTS.md (D3 item 4).** "Git and pull requests" gains a "Naming"
  subsection that states the Work Order, pull request and merge-subject
  rules: the feature, the train address, the scope, the type, the prose,
  and when the rules apply. It no longer points at a document in
  `kottera/kottera` for them. "Other repositories" still names
  `kottera/kottera` as where tera lives, and the conventions mean what
  they meant before.
