# ADR-013 — W2-5: D6's `install.sh`, its tests and its real installs

**2026-10-23, PLAN-2026-10-metais-public W2-5.** `site/public/install.sh`
is D6 item 3's script, and `site/build.sh` serves it at `/install.sh`
(D1 item 5), which `site`'s `TestInstallServed` holds. It detects
`darwin` or `linux` and `amd64` or `arm64`, and refuses anything else
naming `go install` and the release's archives (item 4). It downloads the
archive and `SHA256SUMS` from the GitHub release and refuses on a
mismatch, or on a missing or repeated line (item 5). It installs to
`~/.local/bin` or `$METAIS_INSTALL_DIR`, with no `sudo` and no rc file,
and prints the `PATH` line when the directory is not on `PATH` (item 6).
`METAIS_VERSION` pins a version with or without its `v`. Without it the
script asks GitHub's API for the latest release, which is never a
prerelease or a draft, and on its 404 refuses, saying there is no stable
release yet and naming `METAIS_VERSION` (item 7, and the wave brief's
ruling). It ends by suggesting `metais skill` (item 9).

The script holds no setting that points it elsewhere: its two URLs are
constants. `site`'s `TestInstall`, `TestInstallLatest` and
`TestInstallRefuses` run it as published, through `sh` reading it on
standard input, and change only what `PATH` finds for `curl`, `uname`
and `sha256sum`. The fake `curl` answers from a release laid out in a
temporary directory and records every URL it is asked for, so the tests
also require the script to fetch from `github.com/kottera/metais` and
`api.github.com` and nothing else. `sha256sum` is the test binary, so the
hash does not rest on which tool a host has. The refusals are a hash
mismatch, a missing line, an unknown system, an unknown machine and no
stable release; each was seen red with its check removed.

`ci.yml`'s `install-linux` and `install-macos` jobs (item 8) run
`.github/scripts/install-test.sh`. It tags `HEAD` `v0.0.0-install` in the
job's clone alone and builds that prerelease with `internal/tools/release`.
It serves the archives on `127.0.0.1` at the paths github.com serves them
from, and runs the script with the host's own `curl`, `tar` and hash tool.
A `curl` wrapper on `PATH` sends the two GitHub hosts to that server. The
`jobs` input selects either job, or both as `install`. `internal/guarantees`'
`TestCIWorkflow` holds the jobs, and `TestWorkflows` holds them to D5 item
1.
