# ADR-003 — W2-4: the sample generator honours `coverage` and `uniqueKeys` (Amendment A2)

**2026-10-23, PLAN-2026-10-metais-values-and-rules W2-4.** Amendment A2's
item 17 is built for the generator, and chapter 13 §13.6's MTS-SMP-010 and
MTS-SMP-011 land as `b80ed115` wrote them, after MTS-SMP-004.

- **Item 17, `coverage`.** The first items of an array whose schema holds
  `coverage` each hold one member of `values` at the key, in `values`'
  order, and the array is at least that long, whatever `--items` asks. Each
  such item is a fixed point holding the member at the key, so its other
  fields are generated around it as a supplied value's are. Several
  `coverage` keywords in one conjunction are taken in walk order, a member
  an earlier one already holds at the same key left out.
- **Item 17, `uniqueKeys`.** An item whose key equals an earlier item's,
  compared pointer by pointer by MTS-DAT-013's equality, is regenerated
  under `attempt:<k>` streams, up to 16, as a `uniqueItems` duplicate is.
  The attempt reaches every place below the item, so the key's own value
  changes, and it moves an `enum` or `examples` cycle on by a draw of that
  place's attempt stream, so the columns of a composite key move apart. A
  key of one pointer also steers the author's values at it off the values
  earlier items hold there.
- **When the keys run out.** When `--items` asks for more items than the
  key allows distinct values, the array is shortened to the items it can
  make, as ADR-007 D9 item 16 shortens a `uniqueItems` array. Below
  `minItems` it is `schema.sample_unsatisfiable` with reason `unique_keys`,
  and so is an item holding a `coverage` member whose key cannot be made
  distinct, since that item is never dropped. A `coverage` with more
  members than `maxItems` is reason `coverage`.

Vectors: `smp/sample-coverage`, `smp/sample-unique-keys`,
`smp/sample-coverage-unique-keys` and `smp/sample-unsatisfiable-rules`.
