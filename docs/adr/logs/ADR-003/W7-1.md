# ADR-003 — W7-1: an unreadable data entry and an item name no tree can hold get vectors

**2026-10-20, PLAN-2026-10-metais-v1 W7-1.** The two codes W4-1 left
without a vector each have one now.

- **`input.not_readable`** names MTS-SUP-030. `sup/data-entry-unreadable`
  makes an input's file, a collection's directory and an item's file mode
  0000 through ADR-011 A4's `unreadable` setup. An unreadable item is
  left out of its collection's validation, as an item that does not parse
  is, so that case reports `input.validation.partial` too (MTS-SUP-029).
- **`collection.item_name`** names MTS-SUP-031. `sup/collection-item-name`
  renames two items to `c:d.json` and `e\f.json` when the case runs,
  through ADR-011 A6's `renames`, which the plan orchestrator's ruling of
  2026-10-20 (plan §13) asked for. The committed tree keeps D9 item 8's
  portable names.
- **A name that is not UTF-8** is the code's `encoding` reason.
  `internal/inputs`' `TestCollectionItemNameEncoding` proves it where the
  file system can hold such a name, and skips where it cannot, as APFS
  cannot. It skipped on the darwin host this item ran on, so that half
  was not observed here.
