# ADR-003 — W2-5: each rule shown in words in `schema --fields`, `inspect` and the hints (Amendment A2 item 10)

**2026-10-23, PLAN-2026-10-metais-values-and-rules W2-5.** The first,
second and last bullets of Amendment A2 item 10 are built. The help topic
`metais help schemas`, `help schema`'s pointer to it, the skill and
chapter 13's "Rules across the rows of a table" are W2-6's.

- **`metais schema <package> <input> --fields`.** Directly beneath the line
  of an array whose declaring schemas carry `uniqueKeys` or `coverage`, one
  line per rule says it in words, as ruling R-W2-a places it: the array's
  pointer, `rule`, and "no two rows share `/criterion`", a composite key's
  pointers joined ("`/standard` and `/clause`"), or "rows must include, at
  `/criterion`, each of:" and every value, each as its canonical JSON, as
  the finding's `missing` parameter writes it. A rule declared under a
  condition carries the field line's `when` column. A rule is reached as a
  constraint is, through `$ref` and `allOf` and on an array at any depth,
  and one reached along two paths is stated once. Its values are never
  cut: A16's 1024- and 4096-byte bounds still cut the keyword in the
  constraints column, where it stays as `keyword=<canonical JSON>`.
- **`metais.schema/1`.** Each field gains `rules`, an array, empty for none:
  one object per rule with `keyword`, `pointers` (`uniqueKeys`' key
  pointers in order, or `coverage`'s key alone) and, for `coverage` only,
  `values`. `docs/cli/schemas/metais.schema.1.json` states it, beside a
  `rule` definition. The site copies only the help and version result
  schemas, so no copy of this one is regenerated.
- **`metais inspect`.** An input whose field listing holds a rule says, at
  the end of its line, "has rules across its rows, which metais schema
  <package> <input> --fields lists". The JSON result is unchanged: item 10
  states only the line.
- **The hints.** `input.unique_keys` and `output.unique_keys` say "No two
  items may share `<key>`, and item <index> repeats item <duplicate_of>'s";
  `input.coverage` and `output.coverage` say "Add an item whose value at
  `<key>` is <missing>". The column is the keyword's key pointers as the
  schema writes them, which no parameter of chapter 12's rows carries. So
  the adapter puts them in the failure's data, `keys`, and the mapping
  declares the hint with them, as ADR-006 A4's declared hints carry a
  format's pattern. No finding parameter is added. The registry's
  templates for the four codes say the same with the column unnamed, and
  `spec/findings/registry.json` is regenerated from them. No vector records
  a hint, so no vector expectation changes.

Tests: `internal/schema`'s `TestFieldsRules`, `TestFieldsRulesWhole` and
`TestRuleFailuresNameTheirKeys`; `internal/schemafail`'s `TestRuleHints`
and two cases of `TestMapRefusals`; `internal/cli`'s
`TestSchemaFieldsRules` and `TestInspectRules`. `TestSchemaFields` now
compares the JSON entries with the whole text, rule lines included.
