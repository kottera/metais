# ADR-003 — W1-7: `coverage` evaluated, for inputs and outputs (Amendment A2)

**2026-10-23, PLAN-2026-10-metais-values-and-rules W1-7.** Amendment A2's
`coverage` is built, specified and proved by vectors: chapter 5 MTS-DAT-016
and MTS-DAT-019 and chapter 12 §12.3's `coverage` row, as `b80ed115` wrote
them. It joins `uniqueKeys` in the rules vocabulary W1-6 registered, so the
sentences W1-6 landed naming both keywords (§5.4's opening and example,
MTS-DAT-004, MTS-DAT-017, MTS-FND-004 and MTS-SUP-029) are now true of the
tool, and the window W1-6 opened is closed.

- **Ruling 5 and item 14.** The pre-check holds `coverage` to MTS-DAT-016's
  grammar: an object of exactly `key`, a key pointer, and `values`, one or
  more values no two of which are equal as MTS-DAT-013 compares them. One
  that breaks it is `schema.invalid` naming the keyword, at open.
- **Rulings 6 and 7, item 13.** Each member of `values` no item holds at the
  key is one error finding at the array, `input.coverage` or
  `output.coverage`, its `missing` parameter the member's canonical JSON
  text, as `const`'s `expected` is written. A report orders the findings by
  that parameter, not by `values`' order. An item with no value at the key
  covers nothing.
- **Item 18.** Each item's value at the key is encoded once, by the encoding
  `uniqueKeys` uses, and each member of `values` is looked up once, so the
  evaluation is linear in the items and the package's own values.
  `TestCoverageLinear` holds it to 3 s of CPU at 50,000 values over 99,999
  items: it takes 0.13 s, while a scan of the items' values per member, put
  in its place to check the test, took 8.2 s and failed it.

Vectors: `dat/coverage`, `dat/coverage-grammar`, `sup/coverage-partial` and
`trn/output-coverage`. `TestCoverageUnknown` is turned around into
`TestCoverageGrammar` and `TestCoverage`.
