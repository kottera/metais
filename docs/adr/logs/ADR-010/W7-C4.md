# ADR-010 — W7-C4: the go command a test runs takes no module cache or proxy from the host

**2026-10-20, PLAN-2026-10-metais-v1 W7-C4.** D14 item 1 isolates every
test from the developer's configuration. The tests that build `metais`, or
list the module, ran the go command with the test process's own
environment. On a developer host that sets no `GOMODCACHE`, `GOPATH` or
`GOFLAGS`, four `internal/guarantees` tests failed in their cleanup:
`TestDeterminismDetector`, `TestRenderWithinOpenFileLimit`,
`TestRenderUnderAClosedUmask` and `TestPackDeterminism`.

**The mechanism.**

- **Where the module cache went.** Each test calls `testenv.Home`, which
  points `HOME` at a `t.TempDir()`, and then `buildMetais`, which ran
  `go build` with the test's environment. With neither `GOMODCACHE` nor
  `GOPATH` set, the go command's module cache is `$HOME/go/pkg/mod`, so it
  was inside the temporary directory.
- **What the build did there.** The cache was empty, so the go command
  downloaded every dependency of the module through the host's `GOPROXY`,
  over the network, and extracted them read only, as it always does.
- **Why the cleanup failed.** `t.TempDir`'s `RemoveAll` cannot unlink a
  file in a directory it may not write:
  `unlinkat …/001/go/pkg/mod/go.yaml.in/yaml/v3@v3.0.5/decode_test.go:
  permission denied`.
- **Why the dispatch hosts never showed it.** They set `GOMODCACHE`
  explicitly, so the build read their shared cache whatever `HOME` was.
- **The same exposure elsewhere.** Every other test that ran the go
  command inherited the host's `GOFLAGS`, `GOPROXY`, `GOSUMDB`,
  `GOTOOLCHAIN`, `GOENV` file and workspace. Those are `cmd/metais`'s three
  builds, `internal/version`'s release-flag build, `internal/hostfs`'
  terminal build, `internal/pkgtree`'s `go list`, `internal/conformance`'s
  tool and stub builds and its `go list`, and the selector
  `internal/guarantees` runs. `internal/pkgtree` also calls `testenv.Home`
  first, so it had the same defect.
- **A latent one in the isolated helper.** `internal/guarantees`'
  `moduleCache` asked `go env GOMODCACHE` in the test's current
  environment, the first time any test needed it. Under a test that had
  already moved `HOME`, the answer would have been the temporary
  directory, and the `GOPROXY=off` listing would have failed.

Pinned false first: run as on a plain host, with no `GOMODCACHE`, `GOPATH`
or `GOFLAGS` and a file proxy standing in for the network,
`TestPackDeterminism` failed with exactly the cleanup error above.
`TestGoCommandTakesNoHostGoEnv` fails against the old `buildMetais` on any
host, with `module lookup disabled by GOPROXY=off`.

**What landed.**

- **`internal/testenv`** gains `GoHost`, `GoHostQuery`, `ParseGoHost` and
  `GoEnv`. `GoEnv` gives the whole environment of a go command a test
  runs. It holds `HOME`, the temporary directory and `GOPATH` under a
  directory the caller owns, `GOENV=off`, `GOWORK=off`,
  `GOFLAGS=-mod=readonly -buildvcs=false`, `GOPROXY=off`, `GOSUMDB=off`,
  `GOTOOLCHAIN=local` and `CGO_ENABLED=0`. From the host it takes only
  what `GoHost` names: the module cache the toolchain already holds, its
  build cache, and the C compiler and `PATH` a race build needs. The
  package still reads no environment and runs no command, so the symbol
  rule's allow-list is unchanged. A test takes the host's own environment
  when its package is initialized, before any test moves `HOME`. It asks
  `go env -json` in it, with the toolchain that runs it.
- **Every test that runs the go command** does so through its package's
  `goCommand`, over `testenv.GoEnv`. The race build of
  `internal/conformance` appends `CGO_ENABLED=1`, and `internal/pkgtree`'s
  closure listing does the same, so that it reads the widest closure.
  `internal/guarantees`' `isolatedGoEnv` and `moduleCache` are gone; its
  listings append their target's `GOOS` and `GOARCH` to the same
  environment. The selector that `TestGateSelect*` runs takes it too, over
  the host's environment, so its `go list` reads the host's cache and never
  the network.
- **The build cache is the host's, not a fresh one.** It changes how long a
  build takes and never what it builds. A fresh cache had each build of
  the tool compile the module's whole closure again.
- **`-buildvcs=false`.** No test reads a binary's VCS stamp. With it off,
  whether git is on `PATH`, and whether the tree is dirty, cannot change a
  binary a test builds.
- **The selector's blind packages.** `gate-select.sh` finds the packages
  whose tests run the go command by their test files, which now name
  `testenv.GoEnv(` rather than `exec.Command("go"`. It matches both.
- **The gate's scripts** run the go command as the developer runs it, in
  the developer's own environment, with `HOME` unmoved. The module cache
  is the host's own and never under a directory a script removes, so they
  are not exposed to this defect. They are the developer's build, not a
  test, and they keep `GOTOOLCHAIN=auto` (D1).
