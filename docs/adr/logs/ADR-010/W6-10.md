# ADR-010 — W6-10: schema-work is counted in METAIS's wrapper, and ref-depth is pre-checked

**2026-10-20, PLAN-2026-10-metais-v1 W6-10.** D5's wrapper now counts
`schema-work`, which W2-10 left uncounted because the library has no hook
in its evaluation. `Schema.Validate` counts what a validation would cost
before it calls the library: its own walk of the compiled schema
(`internal/schema/work.go`), over the instance as the data model holds it,
counts every subschema that could apply whatever any evaluation's outcome,
and refuses with a `*regexprofile.LimitError` naming `schema-work`. The
count resolves `$dynamicRef` by the dynamic scope, as the library does,
from the compiled schemas' locations. It matches `patternProperties` in
the order of their patterns, charging `regex-work` as the library will
again. `regexprofile.Meter` carries both budgets, since it is the value
one command's validations already share. Each caller reports the limit
the error names.

D5 item 3's pre-check adds `ref-depth` (`internal/schema/refdepth.go`):
the most references along a chain of subschemas at one instance location,
over the files as authored, each reference resolved as the pre-check
resolved it. The combined schema's pre-check walks its root at depth 0,
so the files it embeds keep their own depths.
