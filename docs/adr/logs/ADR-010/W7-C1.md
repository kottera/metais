# ADR-010 — W7-C1: the git a test or a gate script runs takes nothing from the host

**2026-10-20, PLAN-2026-10-metais-v1 W7-C1.** D14 item 1 isolates every
test from the developer's configuration. `internal/guarantees`'
`TestGateSelectWorkingTree` did not isolate the git it ran. On the wave's
darwin/arm64 dispatch host its clone failed, and every Wave 7 item reported
it.

**The mechanism.**

- **Where the setting comes from.** The host's system configuration sets
  only `credential.helper` and `init.defaultBranch`, and there is no global
  file. `core.precomposeunicode=true` comes from git itself. On darwin, git
  probes the filesystem when it creates a repository. On APFS, which does
  not distinguish a name's normalization forms, the probe writes the
  setting into the new repository's own `.git/config`. It does this for
  every clone, and with `GIT_CONFIG_NOSYSTEM=1 GIT_CONFIG_GLOBAL=/dev/null`
  as well.
- **Why the clone needs iconv.** With the setting on, git passes each
  non-ASCII name that `readdir` returns through iconv's `UTF-8-MAC`
  converter. The repository tracks one such name,
  `spec/conformance/vectors/sup/collections/data/valid/items/é.json`. The
  dispatch sandbox denies reads of `/usr/share/i18n` and `/usr/lib/i18n`,
  where Apple's iconv loads its converters, so `iconv_open("UTF-8",
  "UTF-8-MAC")` fails with `EINVAL`. git then dies with
  `iconv_open(UTF-8,UTF-8-MAC) failed, but needed`. `iconv -f UTF-8-MAC`
  fails the same way on that host.
- **Which invocations it affects.** Only commands that read a working-tree
  directory holding that name: `git status`, `git ls-files --others`,
  `git add --all`, `git clean`, and the go command's VCS stamping. The
  clone and its checkout succeed. Inside the clone, `gate-select.sh`'s
  `git ls-files --others --exclude-standard` died, and the selector exited
  2. A caller's `GIT_CONFIG_*` setting `core.precomposeunicode=false` hid
  the failure because environment configuration outranks the repository's
  own.

**What landed.**

- **`internal/testenv`'s `GitEnv`** returns the environment its caller
  passes, as the environment of a git command a test runs. It drops every
  `GIT_*` variable. It sets `GIT_CONFIG_NOSYSTEM`, `GIT_ATTR_NOSYSTEM` and
  `GIT_CONFIG_GLOBAL=/dev/null`. Through `GIT_CONFIG_COUNT`, it turns
  `core.precomposeunicode` off and points `core.excludesFile` and
  `core.attributesFile` at `/dev/null`, so the XDG ignore and attributes
  files are not read either.
- **`TestGateSelectWorkingTree`'s clone, and the selector both of
  `gate-select.sh`'s tests run,** take that environment.
- **`TestGateSelectWorkingTreeHostGit`** runs the same case under a hostile
  host configuration. A global file has an excludes file that ignores every
  file and turns `precomposeUnicode` on, and the environment turns
  `core.precomposeunicode` on as well. The excludes file changes the result
  on any host. Before the fix, both tests were red on the dispatch host,
  with nothing set by the caller:
  - `TestGateSelectWorkingTree`: the selector exited 2.
  - `TestGateSelectWorkingTreeHostGit`: the planted file was not listed.
- **The gate's scripts** each source `git-env.sh` before their first git,
  which sets the same environment:
  - `gate.sh`, `gate-select.sh`, `gate-why.sh`, `regenerate.sh`,
    `merge-setup.sh` and `merge-check.sh`;
  - the go command they run inherits it.

  Two scripts do not source it:
  - `gate-wait.sh` runs only `git rev-parse --show-toplevel`, which reads
    no working-tree directory.
  - `merge-generated.sh` is the merge driver git runs with the caller's
    repository environment, and runs only `git merge-file` on temporary
    files.

  No other test in the module runs git. The tests that run the go command
  do so outside any repository, or in the caller's own checkout. Under the
  gate, that checkout's git inherits the environment `git-env.sh` set.
