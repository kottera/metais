# ADR-010 implementation log — W5b-1

- **2026-10-19, PLAN-2026-10-metais-v1 W5b-1.** Amendment A5 landed with
  the gate it describes. `.claude/skills/verification-gate/gate.sh` runs the
  scoped tier (`gate.sh`) or the wave tier (`gate.sh wave`), writes one
  record per run with each step's and each package's verdict against the
  working tree's git tree id, and reuses what is still true under
  `--resume`. `gate-select.sh` is A5 item 3's selector: about 200 lines of
  shell over `go list -test`. `gate-why.sh` re-runs one test alone with
  `-race -count=1 -v`, and prints its wall and CPU time.
  - The measurements A5 items 5 to 7 argue from were taken on `main` at
    `c3620dd`, on a 16-core darwin/arm64 host, go1.26.9, with
    `/usr/bin/time -p`.
  - Measuring the test cache found that D15 item 3's
    `go test -race ./...` reused a cached `internal/conformance` and
    `internal/version` verdict after an edit to `internal/cli`. Their
    tests build `./cmd/metais`, which their test binaries do not link, so
    the cache cannot see it. Both tiers now pass `-count=1`.
  - The first version of `gate.sh` reported `GATE DONE: PASS` over a failed
    package, because `go test | tee` took tee's exit status. A planted
    failing test showed it, and the test step now takes its verdict from
    the per-package record.
