# ADR-010 — W6-V1: the selector reaches a Go file in no package

**2026-10-20, PLAN-2026-10-metais-v1 W6-V1.** Wave 6's verification round
planted an untracked `tools/release.go`, build-ignored and without the
licence header. `gate-select.sh` printed only its `changed` line, so the
scoped tier ran the tripwires alone and passed a change on which the wave
tier's `TestLicenceHeaders` fails. `go list ./...` does not list a
build-ignored package, so the in-package rule did not fire, and no test
file names `tools` as a path literal.

A5 item 3 gains a rule: a changed Go file in no package's directory touches
every package whose test files name the module root itself, by as many `..`
as the package's directory is deep, as a literal or a `filepath.Join`.
Naming the root is how a test reads the tree whole, so the rule follows the
readers rather than a list of directories. Today that is `conformance`,
`guarantees`, `liquidspec`, `loader`, `manifest` and `pkgtree`. The ones
that walk every Go file are `internal/guarantees`' `TestLicenceHeaders` and
`TestNoHostFacts` (its `directives` and `canaries`). Their importers are
not tested for it, as for the blind packages.

The selector had no tests. `TestGateSelectReach` in `internal/guarantees`
runs it over the probes of `testdata/gateselect/reach.txt`: three Go files
in no package, every kind of change the verifier showed reached, the
gate-script seam, and a control that reaches nothing.
`TestGateSelectWorkingTree` plants an untracked Go file and deletes a
tracked file in a clone, and measures the change from `HEAD`. Against the
previous script, the `tools/release.go` and `_tools/x.go` probes and the
working-tree test failed. The probes live in testdata because the data rule
reads a test file's path literals as what its package reads: written in the
test, `"tools/release.go"` made `internal/guarantees` a reader of `tools/`,
and the test passed against the script it was written to catch.
