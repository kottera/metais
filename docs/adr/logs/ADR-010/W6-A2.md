# ADR-010 — W6-A2: D15 item 2's budgets measured on the four shipped targets, and revised

**2026-10-20, PLAN-2026-10-metais-v1 W6-A2.** This is plan §6's
calibration act, run at main 84e6337 with go1.26.9 on each target. The
commands are docs/dev/benchmarks.md's, with `GOTOOLCHAIN` set explicitly.
The hosts:

| Target | Host | Load while measured |
|---|---|---|
| darwin/arm64 | an Apple silicon Mac, Apple M2 Max (12 cores), macOS 26.5.2 | not recorded; other work was running on the Mac |
| darwin/amd64 | the same Mac, under Rosetta 2 (`cpu: VirtualApple @ 2.50GHz`) | 1-minute load 3 to 7 |
| linux/arm64 | the same Mac's podman machine (applehv, Fedora 43, 8 vCPU), a Debian 12 container, uid 1000 | host load 5 to 9 |
| linux/amd64 | an x86-64 desktop, AMD Ryzen 5 3600, Ubuntu 26.04.1, bare metal | 0.0 at the start, under 2 throughout |

**The budgets**, as CPU time per operation over six runs:

| Budget | darwin/arm64 | darwin/amd64 | linux/arm64 | linux/amd64 |
|---|---|---|---|---|
| render the 10,000-row table (`BenchmarkRender/table`), ≤ 200 ms | 10–12 ms | 13 ms | 9–11 ms | 29–30 ms |
| `inspect` the 10,000-entry package (`BenchmarkInspect`), ≤ 500 ms | 275–357 ms | 454–486 ms | 279–301 ms | 730–763 ms |
| validate the 10,000-item collection (`BenchmarkValidate`), ≤ 500 ms | 0.89–1.21 s | 0.85–1.47 s | 0.71–0.73 s | 0.96–1.06 s |

**Revised by evidence (Ed, 2026-10-20), as item 2 provides.** The `inspect`
and validation budgets are each **2 s** of CPU, on every supported target.
METAIS is not a performance tool: single-digit seconds for a typical
single-document template is the bar. The new budgets keep each figure above
with margin, and a regression still breaks them. The rendering budget stays
200 ms. Validation spends most of its time in `hostfs` system calls, as
W6-7 found in a sandbox.

**Two things the runbook needs:**
- **benchstat needs `-ignore goos,goarch,cpu`.** Without it, a baseline
  taken on another host forms a table of its own, and nothing is compared.
- **CPU time measured in a VM is evidence only on a quiet host.** The
  podman machine reports no steal time to its guest. Under host load, the
  guest charged short processes for time its vCPUs were descheduled. One
  conformance step that takes 20–35 ms when timed directly was charged
  17–24 s. The linux/arm64 figures here were taken with the host's load
  at 5 to 9.
