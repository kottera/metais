# ADR-010 — W1-4: CI as the third tier of D15, and the workflows tripwire (A8 items 4 and 5)

**2026-10-22, PLAN-2026-10-metais-public W1-4.** Amendment A8 items 4 and
5: D15 gains its third tier, CI on GitHub-hosted runners, and a tripwire
keeps every workflow off self-hosted runners and `pull_request_target`.

- **Item 4.** `.github/workflows/ci.yml` runs the wave tier's list on
  linux/amd64 by calling `gate.sh wave` itself, so the list has one
  definition; `METAIS_GATE_P` is the runner's cores, since a hosted runner
  runs nothing else. Beside it, the race-enabled tests with the build,
  vet and static build on darwin/arm64, the DCO check, `shellcheck` and
  the site's build and tests. Until the flip it runs only on
  `workflow_dispatch`, with an input that runs one job, so a red is proved
  fixed without paying for the others. AGENTS.md states the three tiers.
- **Item 5.** `internal/guarantees`' `TestWorkflows` reads every file
  under `.github/workflows/` through `internal/yamlx`, so it adds no
  dependency. It fails on a workflow with no top-level `permissions`, on
  the `pull_request_target` trigger, and on a job whose `runs-on` is not a
  GitHub-hosted runner's label: `self-hosted` by name, and also any other
  label, a runner group, an expression it cannot read, and a call to a
  workflow outside the repository, since each can reach a runner that is
  not GitHub's. It was seen red against a workflow naming `self-hosted`,
  then one triggered by `pull_request_target`, then one with no top-level
  `permissions`. `TestCIWorkflow` holds `ci.yml`'s trigger, its read-only
  token and its jobs to ADR-013 D5.
