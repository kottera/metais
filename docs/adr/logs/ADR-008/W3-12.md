# ADR-008 — W3-12: an example's inputs are never a real document's data, and the skill routes what a package needs and a script's test data (Amendment A11)

**2026-10-22, PLAN-2026-10-metais-ux W3-12.** Amendment A11 is implemented.
`internal/cli`'s constant `exampleNotFacts` says that an example's inputs
are never a real document's data and that its facts are asked for;
`inspect`'s Examples section prints it after `exampleIs`, and `inspect`'s
help ends with it. `examplesEntries` joins both sentences under "The
entries under examples/ are the package's examples.", and ends the help
of `ls`, `read` and `extract`; `extract`'s example that writes the example
`basic` says its inputs are never a real document's data.
`internal/skill/SKILL.md` gains the sections "What a package needs, when
asked" (`inspect`, then `schema --fields`) and "Testing a script or tool
the person asked for" (`sample` into the working directory), its
fictional-data rule allows testing a script the person asked for, and its
`check` step names the refusal MTS-AUT-003 gives a package that cannot be
read. The repository README's `check` line says the same.

- `supplier_test.go` holds the amendment: `TestExampleInputsAreNeverFacts`,
  `TestSkillRoutesWhatAPackageNeeds`, `TestSkillTestsAScriptOnGeneratedData`
  and `TestSkillCheckSaysTheRefusal`. Each was red against the code before
  the change. `TestInspectExamplesSay`, `TestSupplierHelp` and
  `TestSkillSendsNoSupplierToAnExample`, unchanged, still hold A8's and
  A10's guarantees.
- The help goldens and `skill-print.md` were rewritten by `-update`. No
  chapter of the specification, published schema or vector changes: none
  describes the help, `inspect`'s text output or the skill.
