# ADR-006 — W1-6: `input.unique_keys` and `output.unique_keys` (D6, D7 item 4)

**2026-10-23, PLAN-2026-10-metais-values-and-rules W1-6.** ADR-003
Amendment A2 ruling 7 gives D6's table a `uniqueKeys` row: `internal/finding`
registers `input.unique_keys` and `output.unique_keys`, each naming the
repeating item's `index` and its `duplicate_of`, and the manifest family
registers neither, since the manifest schema never uses the keyword
(ADR-006 A1). The adapter gives one failure per repeated key, and the
mapping locates it as MTS-DAT-018 places it, with the first occurrence in
`related` (D5 item 9's note). `schema.invalid` also reports a `uniqueKeys`
that breaks MTS-DAT-015's grammar, naming the keyword.

**D7 item 4.** An array validated in part reports each `input.unique_keys`
between two items it validated at their original indexes, by the mapping's
existing remapping; the finding is about two items, not the array, so it is
never suppressed (`sup/unique-keys-partial`).
