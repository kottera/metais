# ADR-006 — W7-C6: the findings limit counts the findings within alternatives

**2026-10-20, PLAN-2026-10-metais-v1 W7-C6.** D8 item 5's cap now counts
every finding a report lists, those within an `input.any_of` or
`input.one_of`'s `alternatives` included, at every depth (MTS-FND-020).
They are taken in the order the report lists them: each finding, then its
alternatives branch by branch, each branch's findings followed by their
own. Where the cap is reached within a finding's alternatives, that
finding is listed with what comes before it, each finding left out of a
branch is counted in the branch's `omitted`, and no later finding is listed
but `report.truncated` (MTS-FND-021). The vector is
`fnd/nested-findings-cap`. D6 item 6.4's 16 findings per branch are
unchanged.

- **Why.** A failing `anyOf` nested every failing alternative's findings in
  one finding, and the cap counted only that one. 18 levels of a
  two-branch `anyOf` listed some 500,000 findings in one and wrote 415 MB
  (W7-C5's log, ADR-009).
- **What the mapping holds.** `schemafail.Map` gives each finding to a
  sink as it is made, and keeps one of each duplicate key, as the report
  does. A branch is gathered by `finding.Branch`, which holds the 16 it
  lists. A choice is built listing at most the command's findings limit
  (`Target.Listed`, `finding.WithListedAtMost`), so no one finding holds
  more than a report could list. `inputs` strips a failure tree in place
  rather than copying it.
- **What the report holds.** The bounded heap still holds the first
  `findings` distinct findings by count. What each lists within its
  alternatives is counted when the report is read, because a duplicate
  that replaces a listed finding can list less than it did, and so let in
  a finding after it.
- **The JSON document and the human report** write each finding, and each
  finding within its alternatives, as it is encoded
  (`finding.EncodeJSON`, `finding.EncodeHuman`), so a report of the
  limit's findings is never held as one encoding beside the findings.
- **D6 item 9's field lookup** works each failure's answer out once, from
  its parent's, rather than walking the whole ancestry for each finding. A
  finding holds its parameters as a sorted list. No finding changes.

The measurements are in ADR-009's log entry for W7-C6.
