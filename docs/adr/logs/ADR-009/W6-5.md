# ADR-009 — W6-5: Amendment A1's schema compile bounds are in force

**2026-10-19, PLAN-2026-10-metais-v1 W6-5.** Amendment A1 is implemented
whole. `schema-subschemas` (20,000) and `schema-location-length` (512
bytes) are in `internal/limits`, after `schema-depth`, so `metais limits`
and its JSON list them, `--limit` lowers them and nothing raises them.
Chapter 14 states them in §14.1's table and in MTS-SEC-020 to
MTS-SEC-022, which `sec/schema-subschemas` and `sec/schema-location-length`
prove.

The pre-check of ADR-010 D5 item 3 counts every value its walk enters as
a schema, booleans included, into one tally per compilation. For the
package's schema files, read in byte order of their names, that tally is
the package's total. The first subschema past the bound is reported once,
with the total as `observed`. Each file reports its first location over
the length once. The resource length is the longer of the base the walk
carries, which an `$id` at or above the subschema sets, and the file's
retrieval URI. The combined schema has a tally of its own and is refused
at `.compiled/schema.json` and its first subschema past the bound. Its
locations are not checked, as item 2 says. An output validation
compilation (ADR-005 D11) is pre-checked by the same code. It counts the
files it reaches, in the order it reaches them.

The defaults are not calibrated here. W6-6's suite runs item 5's joint
worst case, and §6's act runs it on each target.
