# ADR-009 — W6-11: the hostile corpus of templates and outputs

**2026-10-20, PLAN-2026-10-metais-v1 W6-11.** D17 items 7 and 8 are in the
corpus. Each case is a `security` vector with its exact findings, one defect
per package (R2-178), or an existing vector named for it. Templates are read
only when a render, `check` or `test` parses them, never by verification at
open (chapter 2's MTS-PKG-032 ends at the manifest, the schemas and the
compiled files). So every template case is met at the render step, as
ADR-011 D16 item 3 places hostility in the render, and no case of either
item is refused at open. The new vectors are:

- `tpl/hostile-partials`: `include`, and `render` of a traversal, an
  absolute name, a name only the working directory's decoy has,
  `.compiled/manifest.json` and an asset; `asset` outside `assets/`; and
  self- and mutually recursive partials, at the default `partial-depth`.
- `tpl/hostile-text`: a template that is not UTF-8, one holding U+0000, and
  `{{ env }}`, `{{ ENV.HOME }}`, `{{ site }}` and `{{ page }}`.
- `sec/hostile-template-work`: 10,000 nested blocks and `(1..1000000000)`,
  at the defaults, which refuse each before its cost is paid. Nested loops,
  string doubling past `value-size` and past `assign-bytes`, `split` past
  `array-size`, `contains` in a loop past `render-work`, and output past
  `output-size` each run at a lowered limit with an input sized to it
  (D4 item 4).
- `pth/hostile-output-paths`: manifest paths in each Windows-invalid form,
  with a reserved name, a control or bidirectional character, or a `.git`
  segment.
- `trn/hostile-containers`: a container entry path that climbs out, written
  and rendered from data.
- `sec/hostile-overwrite`: a path from data that climbs out, rendered into
  an existing output directory holding a link and a FIFO at two output
  paths, with and without `--overwrite`.

`"now"` and `"today"` given to `date` are `flt/date-now-refused`. A template
over `template-size` is `sec/template-size`. Traversal and absolute manifest
paths are `pth/output-path-traversal`. Their data-derived forms, case
collisions among `for_each` items and `.git/hooks/` from data are the
`pth/data-path-*` vectors. Links and FIFOs at output paths are
`rnd/overwrite-link` and `rnd/overwrite-fifo`. `outputs` + 1 is
`sec/outputs`, and a container listing itself is `trn/container-tree`'s
`lists-itself`.

A container lists itself only through a YAML alias, which the manifest
refuses with content-class codes. Every opening command refuses it with the
same two findings, except `check`, which adds the `report.step_skipped` that
chapter 13's MTS-AUT-002 requires once the manifest fails. So a manifest
refusal cannot meet ADR-011 D16 item 3's "the same findings" through every
opening command, and the case stays at its render step.

Item 12's pairs at the bound and past it are `sec/template-size`,
`sec/template-nesting`, `tpl/partial-depth`, the `tpl/charge-*` vectors
(`render-work`), `sec/loop-iterations`, `sec/value-size`, `sec/array-size`,
`sec/assign-bytes`, `sec/outputs`, `trn/container-nesting`
(`container-depth`), `sec/output-size` and `sec/output-total`.
`pth/output-path-limits` and `pth/data-path-limits` cover `path-length` and
`path-depth` on output paths, and the new `trn/container-entry-path-limits`
covers them on container entry paths.

R2-139 is in chapter 14 as a note under MTS-SEC-006: hard links are not
detected when a data directory is read, and a render's rename leaves another
link to a replaced file with its old bytes. R2-149's `container-depth` is
`trn/container-nesting` at the default. R2-150 holds: the one case that
would be large at the defaults runs at a lowered limit.

No case exposed a defect. On a contended darwin/arm64 sandbox, nested loops
of 10,000 by 10,000 took 10.7 s of CPU to reach the default
`loop-iterations`, past D18's 10 s ceiling. A sandbox gives numbers, not
evidence, so the vector runs at a lowered limit. The number goes to the
calibration act (R1-015), and no default is changed here.
