# ADR-009 — W7-C9: Amendment A6's bounds, each path measured, and the render held jointly

**2026-10-20, PLAN-2026-10-metais-v1 W7-C9.** This entry implements
Amendment A6 items 2 to 5 and 9: the whole-document parses no limit
bounded, `output-values` and `yaml-size` on validated outputs,
`input-values` and `output-total` halved with the joint render case, and
`schema-yaml-size`. Item 6, the memory backstop, is W7-C10's.

The host is linux/amd64, a sandbox of 12 CPUs on a host shared with other
Work Orders. Figures are peak resident memory (`ru_maxrss`) and CPU time
of the command as a process, built with `-trimpath` and go1.26.2, because
the host sets `GOTOOLCHAIN=local`. They are a sandbox's figures, not
evidence (plan §5). **All four targets need A3's real-host re-run**:
darwin/arm64, darwin/amd64, linux/arm64 and linux/amd64. "main" is
`7c3b362`; "C9" is this item's branch.

## Item 2: the bounds that need no new limit

Each path was reproduced at main before it was changed (the `root-cause`
skill: measure first). A6's table gives darwin/arm64's figures at the
sizes it names; where that size would take this shared host past a few
GiB, the path was measured at a smaller size and A6's figure is the one to
compare with.

| Path | Case | main | C9 |
|---|---|---|---|
| `.compiled/digests.json` | a 16 MiB digest file of zeros (A6: 64 MiB, 8625 MiB) | 1790 MiB | 45 MiB, refused as `shape` |
| `example.yaml` read as JSON | 8 MiB of zeros (A6: 32 MiB, 3515 MiB) | 947 MiB | 14 MiB, refused before it is read |
| the open's outline of a reference | 16 MiB of headings (A6: 64 MiB, 5791 MiB) | 1501 MiB | 46 MiB; 142 MiB at 64 MiB |
| a manifest's value past `schema-work` | an unknown member of 449,991 zeros | `internal.error`, a panic | `limit.package` naming `schema-work` |

The mechanisms:

- **The digest file** is decoded with a `limits.Counter` bounded at
  `entries` plus 4 (`limits.CounterTo`), given to `jsonx` as A4's input
  readers give theirs. The reading stops at the value past the bound, and
  `digest.Verify` refuses the file with `package.digest.not_canonical`,
  reason `shape`, the finding a file not in its form already had. The
  bound is the limit's, not the package's count: a package holds at most
  `entries` entries, two of which the file never lists.
- **`example.yaml`** is checked against `manifest-size` from its declared
  size before it is read, in either form, and the JSON form is parsed
  under `manifest-size` as the YAML form already was. Over the bound it is
  `example.metadata`, reason `syntax`, which is what the YAML reader's
  refusal already became.
- **No buffer sized by a declaration before its limit admits it.** The
  only reader that allocated by an entry's declared size before a tighter
  limit than `entry-size` checked it was `metais test`'s read of
  `example.yaml`, above. Every other `readEntry` reads an entry the open
  admitted under `entry-size` and `package-uncompressed`, which it checks
  for every entry before any is read; the zip reader's buffers are a
  chunk, or the end-record search's 65,557 bytes.
- **The open's title.** `markdown.Title` runs the block pass keeping no
  heading but the first of level 1. It still reads every line, because a
  link reference definition after the heading decides its text, so the
  title is byte for byte what `Outline` gives. `metais outline` keeps the
  whole outline, unbounded but by `entry-size` at 1.0 (A6 item 7).
- **The manifest's validation.** The manifest schema is compiled under the
  defaults, so a manifest within `manifest-size` can cost more than its
  450,000 units: an array of 449,991 items or more under an unknown
  member. The `regexprofile.LimitError` the validation returns is now the
  package's refusal, `limit.package` naming the limit at its default
  bound, located at `metais.yaml`, where it was a panic. A6 item 2 says
  `limit.exceeded`; the registry makes that code's subject an input, and
  every other limit the manifest breaches, under either profile, is
  `limit.package` about the package, so this item reports it so.

**Measured, not bounded here.** The title's pass holds every link
reference definition's label, as the outline's does: a 64 MiB reference
of distinct definitions, `[a1]: b` lines, peaks at 986 MiB on this host,
286 MiB at 16 MiB. Neither A6's table nor item 7 names it; it is held by
item 6's backstop until a later release bounds it.

## Item 3: `output-values`, and `yaml-size` on validated outputs

A validated output's values are counted by a counter of its own,
`lim.Counter(limits.OutputValues)`, given to the output's reader, so each
output is bounded apart from the others (MTS-SEC-063). A YAML output
longer than `yaml-size` is refused before it is parsed (MTS-SEC-062).
Both refusals are `limit.exceeded.output`.

| Case | main | C9 |
|---|---|---|
| a 10 MB JSON output of 5,000,000 values | 1334 MiB | 298 MiB, refused by `output-values` |
| a 10 MB YAML output of 5,000,000 values | 1793 MiB | 63 MiB, refused by `yaml-size` |

## Item 4: the joint render case, and `output-values`'s default

`input-values` is 500,000 and `output-total` 256 MiB. The joint render
case is two calibration cases, one for each last output, so the costlier
is always measured: `render-joint-json` and `render-joint-yaml`. Each
supplies `[[{},{},…]]` and plain text files of `input-size` at most,
exactly `input-values` values and `inputs-total` bytes, under an input
schema that applies to the input's root alone, so its `schema-work` is
small, the validation runs and the library copies the whole value. Then
outputs of `output-size`, exactly `output-total` with the last, and last
the validated output: a JSON array of empty objects of exactly
`output-values` values, the costliest value for its count (A4 item 3), or
a YAML flow sequence of zeros of exactly `yaml-size` bytes, as many as
`output-values` allows.

A4's own joint cases change with `input-values`: a YAML document of zeros
at `yaml-size` holds 524,288 values, more than 500,000, so their last
document, and the `yaml-size` case's, holds at most half of `input-values`,
padded to its size. Their lowered forms lower `input-values` to 30,000, so
that they stay the default case scaled down.

`render-joint-json` at each candidate default, run three times or more:

| `output-values` | Peak |
|---|---|
| none validated (2 values) | 722 to 855 MiB |
| 100,000 | 765 to 794 MiB |
| 200,000 | 833 to 854 MiB |
| 300,000 | 922 to 948 MiB |
| 400,000 | 992 to 1000 MiB |
| 440,000 | 1000 to 1024 MiB |
| 450,000 | 994 to 996 MiB |
| 500,000 | 1020 to 1026 MiB |
| 1,000,000 | 1161 to 1166 MiB |

`render-joint-yaml` peaks at 993 to 1003 MiB whatever `output-values` is
from 400,000 up: yaml/v3 builds the whole document's tree before any value
is counted.

**`output-values` is 400,000.** 500,000 breaks the ceiling. 450,000's
case at the limit stays within it, but only because an output of 450,000
values passes the `schema-work` the inputs leave, so it is parsed and
refused before the library copies it; an output of 440,000 values, within
that default, is copied and peaked at 1024 MiB. 400,000 is the largest
round value whose case at the limit is also the costliest output the
default admits, and it peaks no higher than the YAML output at
`yaml-size`, which is the case's floor. The case breaks no ceiling with
no validated output, nor at 100,000, so A6 item 4's order of giving way is
not reached. **The margin is thin**: the joint case peaks at 97 to 98% of
1 GiB on this host, and W6-A2 measured darwin/arm64 about 12% above the
other targets. The real-host re-run is what settles it; a target where it
breaks gives way as A6 item 4 orders, `yaml-size` first, by a further
amendment (R1-015).

## Item 5: `schema-yaml-size`

A YAML schema file, `.yaml` or `.yml`, longer than `schema-yaml-size` is
refused with `limit.package` before it is read (MTS-SEC-061), by
`schema.SizeBreached`, which the compiler and `SchemaPositions` share. A
4 MiB YAML schema file peaked at 1376 MiB at main (A6: 1372 MiB) and is
now refused at 23 MiB. Its default is A4 item 3's rule for `yaml-size`,
the largest power-of-two MiB whose case alone, `const: [0, …]`, peaks
within 40% of 1 GiB (410 MiB), three runs each:

| `schema-yaml-size` | Peak |
|---|---|
| 512 KiB | 150 to 164 MiB |
| 1 MiB | 221 to 311 MiB; 308 to 336 MiB in the suite |
| 2 MiB | 436 to 592 MiB |

**`schema-yaml-size` is 1 MiB.**
