# ADR-009 — W7-C10: Amendment A6 item 6's memory backstop

**2026-10-20, PLAN-2026-10-metais-v1 W7-C10.** This item builds A6 item 6:
`metais` watches its own Go-managed memory, and past 1.5 GiB stops the
command with `internal.memory`. Sibling W7-C9 builds A6's bounds; this
item changes no limit.

## What landed

- **`internal/backstop`** holds the backstop. `Run` sets the runtime's
  soft memory limit to 1 GiB (`runtime/debug.SetMemoryLimit`), reads the
  memory once before the command starts and then every 10 ms while it
  runs, and stops it at the first read past the ceiling. The memory read
  is `/memory/classes/total:bytes` less
  `/memory/classes/heap/released:bytes` from `runtime/metrics`: what the
  runtime has mapped from the operating system, less what it has handed
  back. A read allocates nothing.
- **`cli.Main`**, the entry `cmd/metais` calls, runs the command under
  `backstop.Run`. `cli.Run`, which every in-process test drives, runs
  none, so a test's memory never stops another test's command.
- **`internal.memory`** joins the registry: class `internal`, subject
  `invocation`, the one parameter `tool_version`, exit 2. Its message
  names no amount. Its hint says whether it stops again depends on the
  machine, where `internal.error`'s says a re-run meets the same defect.
  Chapter 12's catalog, the specdata copies and the help's exit-code
  table follow. No statement needs it: like `internal.error`, it is a
  defect of the tool, not a rule of the format, so it cites none and
  takes no MTS-FND number.

## How the command stops while another goroutine allocates

Go cannot interrupt a goroutine from outside it: nothing makes a
goroutine in the middle of a parse return or panic. The parsers that
reach the backstop are the ones that do not stop by themselves, so a
cancelled context would not stop them either. So the backstop does not
try to stop the command. It runs the command on a goroutine of its own,
and when the memory passes the ceiling it:

1. **Seals both streams.** The command writes through a gate on each
   stream, and the backstop takes both gates' locks. A write in progress
   ends first, so no line is cut in two by the report, and no write
   starts after: a later write blocks for the rest of the process, and
   returns no error the command could go on to report. A gate keeps its
   stream's file descriptor, so a command still tells a terminal apart.
2. **Lets a finished command stand.** If the command returned while the
   streams were being sealed, its whole result is written, and its
   status is the run's.
3. **Cancels the command's context**, so a command that checks it stops
   sooner. Nothing relies on that.
4. **Reports the stop through the normal path.** `cli.memoryStop` reads
   the command line again and emits one `internal.memory` finding
   through `session.emit`, in the command's format, on the stream its
   report would use: standard output for `--json`, standard error for a
   human report or a render to standard output. It reads the line again
   because the command's own session belongs to the goroutine still
   running.
5. **Returns the status**, 2. `cmd/metais` passes it to `os.Exit`, which
   ends the command where it stood.

Rejected:

- *Calling `os.Exit` from the watcher.* `os.Exit` is `cmd/metais`'s alone
  (ADR-009 D14 item 4), and an exit there would not report the stop.
- *A panic in the watcher.* An unrecovered panic in another goroutine
  ends the process with a traceback, which D18 item 2 counts as a crash,
  and which reports no finding.
- *Waiting for the command to notice a cancelled context.* The paths that
  reach the backstop are the ones that do not stop by themselves.

What the stop does not do: no deferred clean-up of the command runs, so
what it was writing is left as a killed process leaves it. A render
prepares its outputs in a staging directory beside the output directory
and renames them into place, so no file of the output tree is half
written. But the staging directory stays, and the next render is refused
with `output.destination.staging_exists` until it is removed. A
command stopped in the middle of writing its own report has its report's
first part on the stream before the stop's report. A command stopped
then has finished its work, so this happens only when the report alone
passes the ceiling.

## Not a limit, and no host fact

- The ceiling is a package variable that nothing outside
  `internal/backstop` sets. It is not in D3's table, `metais limits`
  does not list it, and no flag, environment variable or package moves
  it. The lowered ceiling the tests need comes through package-internal
  seams:
  - the backstop's own tests run its watcher with a ceiling, a meter and
    an interval of their own;
  - the subprocess tests use the **memory canary**,
    `internal/backstop/canary_memory.go`, built only with the
    `metais_canary_memory` tag. Its ceiling is zero bytes, so every
    command it runs stops. The canary rule of `TestNoHostFacts` keeps it
    out of every release build, and the release builder refuses a build
    with any canary tag.
- **The figure goes nowhere.** It is compared with the ceiling and
  dropped. A `Stop` is given the two streams and nothing of the memory,
  so the report cannot hold it. `TestNoFigure` scans both streams for the
  figure, in decimal, hexadecimal, KiB, MiB and GiB. It is pinned false
  first: the watcher's test-only `leak` field writes the figure to
  standard error, and the scan must see it.

## The symbol rule and the layers

`TestNoHostFacts`'s symbol rule refuses none of what the backstop uses:
not `runtime/metrics`, not `runtime/debug.SetMemoryLimit`, not
`time.Sleep`. The watcher waits with `time.Sleep`, which reads no clock
and hands nothing to the program. The timers and tickers the rule
refuses deliver the clock's reading. So the module allow-list is
unchanged, and `TestModuleAllowListIsR2143` still pins R2-143 and A2's
entry. Instead, `internal/guarantees/layers.json` keeps the backstop's
reach narrow with four rules:

- only `internal/backstop` imports `runtime/metrics`;
- only `internal/backstop` refers to `runtime/debug.SetMemoryLimit`;
- only `internal/cli` imports `internal/backstop`;
- `internal/cli` refers to it only in `Main`.

## The harnesses fail a backstop exit (D18 item 2)

- **The corpus runner** gains the `memory-backstop` check. A command
  that exits 2 with `internal.memory` on either stream fails its case on
  that check, as a conformance failure, not a harness error. Both the
  `cli` adapter and the SC7 harness's every-command reach apply it. The
  self-proof's fake gains the `memory` fault, which reports
  `internal.memory` with exit 2, so the check has a fault that breaks
  it. That keeps `TestSelfProofCoversEveryCheck` whole.
- **The calibration suite's** `runCal` ends a run that exited through the
  backstop with an error, so `judgeCase` records it as the case's
  problem. Before this, a gap case, which expects not to reach its
  limit, would have passed.
- **`TestHarnessesFailTheBackstop`** forces a case over the lowered
  ceiling by building the memory canary. It runs one vector through the
  runner, and one calibration case at its lowered limits through
  `runCase` and `judgeCase`. Each must fail, and must fail because of the
  backstop.

## The polling cost

On this item's host (darwin/arm64, a sandbox shared with other Work
Orders, go1.26.2), one read takes about 190 ns. An idle watcher costs
about 9 ms of CPU over 10 s, against 31 µs for the same process
sleeping without it: about 0.09% of one core. That figure was measured
with `getrusage` over a command that sleeps for 10 s, in a throwaway test
that is not committed. The cost is the sleeping goroutine's wake-up
every 10 ms, not the read. These are a sandbox's figures, not a budget.

## Proofs and gaps

- `internal/backstop`: the figures of A6 item 6, that `Run` sets the
  soft limit, and the meter, which reads more than a live 256 MiB and
  allocates nothing. The stop is proved mid-allocation with the real
  meter at a ceiling 64 MiB above the process's own. Further tests prove
  the seal, a command that ends first, a process already over the
  ceiling, `TestNoFigure`, and that a stream keeps its file descriptor.
- `internal/cli`: `TestMemoryStop` checks the report's format, stream,
  status and parameters for a human line, `--json` lines, a render to
  standard output, and a line that does not parse.
- `cmd/metais`: `TestMemoryBackstop` runs the memory canary as a process.
  Each command exits 2 with `internal.memory`, and its JSON document
  validates against its schema.
- **Gap: linux.** Every proof above ran on darwin/arm64 only. The
  backstop has no platform-specific code, and the gate's cross vet and
  build cover linux. But this item had no linux host, so the stop has not
  been observed there.
