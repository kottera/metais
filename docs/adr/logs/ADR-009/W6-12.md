# ADR-009 — W6-12: the hostile corpus of D17 items 9 to 11, and the data, grep and result limits at their bounds

**2026-10-20, PLAN-2026-10-metais-v1 W6-12.** Every case D17 items 9 to 11
names is a `security` vector, an earlier vector, a test of the command line
where no operation of chapter 15 runs the command, or, for a device, an
`internal/hostfs` unit test. The inputs' hostility is refused at `validate`
and at `render`, and nothing is written anywhere.

- **Item 9, inputs from a hostile supplier.** `sec/hostile-inputs` runs
  each case through `validate` and `render`:
  - `links`: a link pointing out, one pointing inside, a linked collection
    directory and a two-link loop, each refused as `input.link`;
  - `fifo`: a named pipe as an input and as a collection item, refused
    unopened;
  - `names`: collection items named with a newline, an escape sequence and
    a bidirectional override, carried exactly in the JSON findings;
  - `echo`: a member name holding terminal escapes, echoed exactly;
  - `bombs`: YAML billion laughs, a JSON array nested 10,000 deep, and a
    frontmatter of anchors and aliases and one nested 10,000 deep, at the
    defaults.

  `sec/data-directory-entries` stands for the links and pipes as
  `validate` first met them, `sec/data-limits` for the inputs over their
  limits, and `sup/csv-structure` for the ragged CSV. The device cases are
  `internal/hostfs/hostile_devices_unix_test.go`, beside W2-5's
  `device_unix_test.go`. `internal/cli`'s
  `TestHostileNamesAndValuesNeutralised` holds the human output of
  `validate` and `render` to D15 item 3, and JSON to the exact text.
- **Item 10, Markdown.** `internal/cli`'s `TestHostileMarkdown` builds
  every case cmark's pathological suite names, in its own words, and runs
  each through `outline` and through a Markdown input's frontmatter
  splitting in `validate`, each run within D18's 10 s of CPU. `outline` is
  not an operation of chapter 15, so no vector runs it.
- **Item 11, commands.** `internal/cli`'s `TestHostileGrepPathological`
  (`(a|aa)*b` over the largest entry a lowered `entry-size` admits),
  `TestHostileGrepPattern`, `TestHostileGrepMatches`,
  `TestHostileGrepContext`, `TestHostileUnpackPlantedLink`,
  `TestHostileExtractPlantedLink` and `TestHostileLimitFlag`. `limit.invalid`
  is of class usage, which the command line's tests prove and no vector
  carries.

**Item 12's pairs.** `sec/data-limits-bound` pairs `input-size`,
`inputs-total`, `csv-rows`, `csv-columns`, `csv-cell`, `collection-items`,
`frontmatter-size`, `value-depth` and `findings`, at the bound and one past
it, under MTS-SEC-058. `regex-work`, `pattern-length` and `regex-program`
for `grep`, `grep-matches` and `grep-context` are paired in the grep tests
above. `findings` and `grep-matches` truncate with a marker (D2 item 6).

Two defects behind these cases are fixed. A lowered `grep-matches` left
`--max-results` at its default of 100, so `grep` reported more matching
lines than the limit; the default is now capped by it. And `jsonx` bounded
every JSON text by `input-size`, so a caller lowering that data limit had a
package refused: a JSON schema or manifest as `limit.package` naming
`input-size`, and a valid packed package as `package.digest.not_canonical`.
The package's own JSON is now bounded by `manifest-size`, `schema-size`
and, for the digest file, `entry-size`.

`TestConformance`'s default run, the compiled test binary alone and not
race-built, on a shared 12-core linux/amd64 host, took 20.1 s of wall time
(93.7 s user, 57.2 s system) at `-test.parallel` 4, and 23.0 s at 12.
