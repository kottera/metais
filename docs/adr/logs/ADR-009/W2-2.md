# ADR-009 — W2-2: D3's output bounds hold on the bytes a render writes

**2026-10-21, PLAN-2026-10-metais-render-seams W2-2.** D3's `output-size`
and `output-total` bound the bytes a render writes, and a transform that
lengthens a rendered file is now charged for it:
`template.Renderer.ChargeChange` counts the change against both limits on
the meter that counted the rendering, and a file the CRLF conversion takes
beyond either is refused with `limit.exceeded.output`, naming the file and
the limit. Before, the conversion's growth, up to the file's own length
again, was written uncounted. MTS-SEC-010 in `spec/14-security.md` says
plainly that an output's bytes are those the render writes, after every
transform; the vectors `sec/output-size-crlf` and `sec/output-total-crlf`
prove both limits.
