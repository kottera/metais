Getting started

This page assumes metais is installed. In the commands below, report.metais stands for your package file, data for a directory of input data, and greeting for one of the package's inputs. Every command ends by printing the commands to run next, and metais help <command> explains any of them in full.

Do not unzip the package. A .metais file is a zip archive, but metais reads it in place and verifies every entry as it does. Everything below works on the file as you received it.

Use a package someone gave you

A package turns data you supply into finished documents. The route is: find out what it needs, gather that data into a directory, validate it, and render.

1. Find out what the package needs

metais inspect report.metais

inspect verifies the whole package first, then prints its title and description, the author's guide, each input with the file names it is read from (such as greeting.json or greeting.yaml), the outputs it renders, its examples, and the commands to run next. Read the guide: it is the author's instructions.

2. Read what each input means

metais read report.metais inputs/greeting.md
metais schema report.metais greeting

Each input has a meaning document, which says what the data is and what good data looks like, and a JSON Schema, which says its exact shape. read prints any entry of the package; ls, outline and grep list, outline and search its entries. The package's examples are complete, valid inputs you can copy from:

metais ls report.metais examples/ -r
metais read report.metais examples/basic/inputs/greeting.json

3. Gather the data in a data directory

Make a directory, here data, and put in it one file per input, named after the input with the extension of its form, as inspect listed: data/greeting.json. A collection input is a directory of files instead. metais help inputs gives every rule, including how to supply or override single values on the command line with --set, --set-json and --inputs-json.

To start from a complete file of the right shape, generate placeholder data from the schemas and replace its values with real ones:

metais sample report.metais --to data

4. Validate the data

metais validate report.metais --data data

Every problem is reported in one run, each with where it is and why. Fix them and run it again until it reports 0 errors.

5. Render the documents

metais render report.metais --data data --out out

render validates the data again, renders every output in memory, and writes them into the new directory out only if all of them succeed. --dry-run lists what it would write and writes nothing; an existing, non-empty out needs --overwrite.

Rendering is pure: no code from the package runs, nothing is fetched from the network, and the same package and data give the same bytes on every platform.

Write a package

The route is: start from a scaffold, edit it, preview it, and pack it once its checks and examples pass.

1. Start from a scaffold

metais init my-report

This writes a small package that already checks, tests and packs: metais.yaml (the manifest, with the title, description and guide), one input under inputs/ with its schema and meaning document, one template under templates/, and one example under examples/ with its inputs and expected output.

2. Edit it, and preview from sample data

Change the manifest, the inputs and the templates. Templates are Liquid, in the dialect the specification pins. Preview the outputs from data generated from your schemas:

metais render my-report --sample --out preview

3. Check it

metais check my-report

check needs no data. It checks the manifest, every schema, every template and the references between templates and schemas, and reports every finding of every step at once.

4. Test its examples

metais test my-report

Each example under examples/<name>/ has its inputs/ and the expected/ outputs a render should write; test renders each one and compares them byte for byte. To add an example from generated data, and to write an example's expected/ from its render once you have checked it:

metais sample my-report --example second
metais test my-report --update

5. Pack it

metais pack my-report

pack runs check and test and refuses to write a package whose checks or examples fail. Otherwise it writes my-report-<version>.metais, the same bytes from the same sources every time. That file is what you give to the people who supply the data. metais unpack turns a package back into a source directory.
